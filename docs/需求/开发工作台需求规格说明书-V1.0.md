## 1 引言

### 1.1 编写目的

本文档描述"开发工作台"（AI 辅助开发工作台）项目的业务需求、功能需求、非功能需求、接口需求、数据需求与验收标准，作为产品设计、开发、测试与验收的依据。

预期读者：项目经理、产品设计人员、开发团队、测试团队。

### 1.2 项目背景

随着大模型编程工具（外部 IDE Agent）的普及，开发团队的瓶颈正从"写代码"转移到"规划与喂料"：需求不清、任务拆分粒度失控、提示词质量参差、过程文档散乱。开发工作台定位于开发全流程的**规划侧**，覆盖"需求探索 → 目录规范 → 提示词工程 → 测试用例"链路，产出规范文档与可直接投喂外部 IDE 的提示词，帮助团队以可控、可追溯的方式驱动 AI 执行侧完成开发。

本项目由材智科技提出并实施，供内部团队局域网共享使用。

### 1.3 术语与缩略语

| 术语 | 说明 |
|------|------|
| 外部 IDE Agent | 部署在开发者侧、可执行代码修改的 AI 编程工具（如 Trae、Cursor、Codex CLI 等），是本产品的下游消费者 |
| Provider | 大模型接入层抽象，屏蔽官方 API 与中转站差异 |
| 模块池 | 提示词工程内置的开发流程模块集合（需求/概设/原型/详设/数据库设计/后端开发/前端开发/测试/回归/验收） |
| 上下文窗口上限 | 外部 IDE Agent 单次可消化的最大上下文长度，是任务拆分的粒度预算依据 |
| 断点续跑 | 流水线中途中断后，从最近已确认步骤恢复继续执行的能力 |
| drawio | 开源图表工具，.drawio 文件为 XML 文本格式，可版本化、可程序化生成 |
| codegraph | 代码结构索引工具，将代码解析为"符号+关系"图以压缩上下文消耗 |
| 工程规则 | 项目级持久化配置（技术栈约定、编码规范、目录约定），生成提示词时自动注入 |

## 2 总体描述

### 2.1 产品概述

开发工作台是一个部署于局域网、团队共享使用的 Web 应用，定位于 AI 辅助开发全流程的规划侧。产品不直接生成或修改代码，而是通过三条能力链路产出开发资产：

1. **需求探索 Agent（F1）**：多角色流水线（需求师→设计师→评审师）引导用户将模糊想法沉淀为规范需求文档，每步产出经用户确认后推进；
2. **目录结构治理（F2a/F2b）**：为新项目按模板一键生成规范目录骨架；对存量项目通过浏览器本地目录扫描给出规整建议；
3. **提示词工程（F3/F4）**：以 10 模块动态组合引擎，按任务复杂度自动选择开发流程模块，按外部 IDE 上下文窗口上限拆分任务单元，逐模块生成提示词与测试用例，支持预览微调、版本管理与按项目归档。

产品全部数据以 Markdown 与 .drawio 等文本格式存储于文件系统，天然兼容 Git 版本管理与团队协作。

### 2.2 产品功能概览

| 功能编号 | 功能名称 | 概述 |
|----------|----------|------|
| FR-01 | 需求探索 Agent | 多角色流水线需求引导与文档生成，每步确认 |
| FR-02 | 新项目初始化 | 模板化一键生成规范目录骨架 |
| FR-03 | 已有项目规整 | 浏览器本地目录扫描分析与整改建议 |
| FR-04 | 提示词工程 | 动态模块组合、上下文预算任务拆分、提示词生成/预览/脱敏 |
| FR-05 | 测试用例生成 | 功能/业务必选、性能可选的测试用例与回归提示词 |
| FR-06 | 流水线持久化与断点续跑 | 每步实时存档，中断可恢复 |
| FR-07 | 项目与提示词库管理 | 项目资产归档、版本管理、执行状态跟踪、效果反馈 |

### 2.3 用户特征与角色定义

| 角色 | 描述 | 权限 |
|------|------|------|
| 团队成员 | 局域网内任意成员，具备基本软件开发协作能力 | 创建项目、运行流水线、生成/编辑/导出提示词、标记执行状态。第一版无权限区分，数据模型预留多用户扩展（CON-03） |

### 2.4 运行环境

| 类别 | 要求 |
|------|------|
| 服务端 | 一台局域网内主机（Windows/Linux 均可），Python 3.12+ 运行时 |
| 客户端 | Chrome/Edge 现代浏览器（FR-03 依赖 File System Access API，见 CON-06） |
| 网络 | 局域网可达；第一版不做公网暴露（CON-02/NFR-03） |

| 编号 | 约束 |

## 3 功能需求

### 3.1 业务流程描述

产品主业务流程（文字版，drawio 图见附录 A）：

```
创建项目（选模板初始化目录 FR-02）
   ├─→ 需求探索流水线 FR-01（需求师→设计师→评审师，每步确认，支持断点续跑 FR-06）
   │        ↓ 产出：需求文档（Markdown）
   ├─→ （存量项目）浏览器选目录扫描分析 FR-03 → 规整建议 → 人工确认归位
   │        ↓
   └─→ 提示词工程 FR-04：
         手动选择上下文（项目文档）+ 工程规则自动注入
         → agent 自动选择模块组合（≥需求+任意开发+测试+验收）
         → 按外部 IDE 上下文窗口上限拆分任务单元（含依赖顺序）
         → 逐模块生成提示词 → 预览/人工微调 → 脱敏扫描 → 定稿
         → 测试模块生成测试用例 FR-05（功能/业务必选，性能可选）
              ↓
   交付：一键复制 / 导出文件 / 按项目归档入库 FR-07
         → 投喂外部 IDE 执行 → 人工标记执行状态 / 记录效果反馈
```

### 3.3 功能需求详细描述

#### 3.3.1 FR-01 需求探索 Agent

- **功能描述**：内置多角色 Agent 流水线（需求师→设计师→评审师），引导用户将模糊想法逐步澄清为规范需求文档。每一步产出必须经用户确认后方可进入下一步；架构师、测试师等角色以可插拔方式扩展流水线。
- **输入**：用户初始想法文本；过程中用户的确认意见与修改意见；可选的项目上下文文档。
- **输出**：阶段产出（需求摘要、澄清记录、评审意见）与最终需求文档（Markdown）；需求文档配图（业务流程图等）以 .drawio 格式产出（CON-12）。
- **业务规则**：
  1. 流水线角色顺序默认 需求师→设计师→评审师，用户可启用/停用扩展角色；
  2. 每步产出落盘保存后才允许推进（支撑 FR-06）；
  3. 评审师角色可给出"通过/修改后通过/退回重做"结论，退回时指明修改点。
- **异常处理**：模型调用失败时保留当前步骤状态与已生成内容，提示重试或切换 Provider；用户中途退出不丢失任何已确认产出。

#### 3.3.2 FR-02 新项目初始化

- **功能描述**：用户选择目录模板，系统在项目工作区内一键生成规范目录骨架及占位说明文件。
- **输入**：项目名称、所选模板（内置默认或用户自定义，CON-05）。
- **输出**：项目目录骨架（含 README、docs/需求、docs/过程档案、src 等模板定义的结构）。
- **业务规则**：
  1. 内置至少 1 套默认模板；模板以可编辑的目录清单文件描述；
  2. 用户可将任意目录结构保存为自定义模板复用；
  3. 目标路径已存在同名目录时必须阻断并提示。
- **异常处理**：磁盘写入失败时回滚已创建条目并提示；模板文件损坏时提示修复或重置为默认模板。

#### 3.3.3 FR-03 已有项目规整

- **功能描述**：用户在浏览器中选择本地项目目录，系统在浏览器端扫描目录结构并进行分析，给出规整建议（可归位文件、缺失的规范目录、结构异常等），经用户确认后生成整改方案。数据不上传服务端，仅分析结果进入系统。
- **输入**：用户经 File System Access API 授权的本地目录（只读）。
- **输出**：项目结构画像（语言构成/目录健康度/依赖关系摘要）与规整建议报告（Markdown）。
- **业务规则**：
  1. 扫描在浏览器端完成，源文件内容不出本机（CON-06）；
  2. 分析引擎可结合代码结构索引（CON-11）生成结构摘要，压缩所需上下文；
  3. 建议区分"自动归位（低风险）"与"需人工决策"两级。
- **异常处理**：浏览器不支持 File System Access API 时明确提示改用 Chrome/Edge；超大目录扫描提供深度/条数上限并提示；授权被拒绝时给出引导说明。

#### 3.3.4 FR-04 提示词工程

- **功能描述**：产品的核心引擎。基于用户选定的上下文（需求文档、项目文档）与项目级工程规则，自动选择开发流程模块组合，按外部 IDE 上下文窗口上限拆分任务单元，逐模块生成可直接投喂外部 IDE 的提示词。
- **输入**：用户手动勾选的项目内文档（需求文档等）；项目级工程规则（技术栈约定/编码规范/目录约定，自动注入）；任务复杂度与层面描述；上下文窗口上限参数。
- **输出**：带依赖顺序的任务清单（DAG/编号序，标明可并行与先后关系）；逐任务逐模块的提示词集合；脱敏扫描报告。
- **业务规则**：
  1. **模块池**：需求、概设、原型、详设、数据库设计、后端开发、前端开发、测试、回归、验收共 10 个模块；
  2. **自动组合**：agent 依据任务复杂度与所处层面自动选择模块组合，用户可干预调整；
  3. **硬约束**：任意组合必须包含 需求 → 任意开发类模块 → 测试 → 验收 最少四模块；
  4. **拆分预算**：模块内任务单元以外部 IDE 上下文窗口上限为粒度预算，超预算任务必须继续拆分；
  5. **工程规则注入**：项目级工程规则自动注入每个提示词，无需用户重复勾选（CON-09）；
  6. **预览微调**：每条提示词生成后进入预览态，支持人工编辑微调后定稿，未经定稿不可归档导出；
  7. **脱敏扫描**：复制/导出前扫描疑似密钥、密码、内网地址，命中项提示用户脱敏确认（参考 OWASP Agentic 风险）；
  8. 提示词模板版本与生成参数一并归档，保证可复现。
- **异常处理**：模型输出超预算未拆分时自动触发二次拆分；模块组合不满足硬约束时阻断生成并说明缺失模块；脱敏扫描服务异常时阻断导出并提示（宁可阻断不可放行）。

#### 3.3.5 FR-05 测试用例生成

- **功能描述**：由提示词工程的「测试」模块承载，为任务单元生成测试用例；「回归」模块独立生成回归测试提示词。
- **输入**：任务单元及其关联的需求条目、设计产物。
- **输出**：测试用例集（Markdown，含前置条件/步骤/预期结果）；回归测试提示词。
- **业务规则**：
  1. 测试用例必须覆盖**功能测试**与**业务测试**两类；
  2. **性能测试**为可选项，用户显式选择后生成；
  3. 每条用例标注其覆盖的需求/任务编号，保证可追溯。
- **异常处理**：需求条目缺失时提示先补全关联需求再生成；生成结果不满足覆盖要求时支持重生成并保留历史版本。

#### 3.3.6 FR-06 流水线持久化与断点续跑

- **功能描述**：所有流水线（FR-01 需求探索、FR-04 提示词工程）的每一步产出与状态实时落盘；用户中途关闭浏览器后，重新打开可从最近已确认步骤恢复继续。
- **输入**：流水线运行时状态（当前角色/步骤、已确认产出、待确认草稿）。
- **输出**：项目目录内结构化的状态存档（Markdown + 状态索引文件）。
- **业务规则**：
  1. 产出确认动作与落盘动作原子完成，先落盘后推进；
  2. 恢复时列出项目内所有未完结流水线及断点位置；
  3. 状态存档为人类可读文本，便于 Git 协作与差异审阅。
- **异常处理**：写入失败时阻断推进并保留内存态供重试；存档损坏时从最近完好存档恢复并明确提示回退位置。

#### 3.3.7 FR-07 项目与提示词库管理

- **功能描述**：以项目为单位归档全部资产（需求文档、任务拆分、各模块提示词、测试用例、结构画像与规整报告），并提供版本管理、执行状态跟踪与效果反馈能力。
- **输入**：各功能产出物；用户的状态标记与反馈备注。
- **输出**：项目资产库（文件系统 Markdown/.drawio 组织）；提示词版本历史；项目进度看板。
- **业务规则**：
  1. 提示词每次修改保留历史版本，支持任意两版差异对比与回滚（G1）；
  2. 任务清单支持手动标记执行状态：待投喂/已投喂/已完成/失败（G5），形成看板视图；
  3. 每条提示词可记录一行执行结果备注（成功/失败/返工原因）（G6）；
  4. 归档结构 Git 友好，无锁定格式（CON-07）。
- **异常处理**：版本合并冲突（多人同时改）第一版不做自动处理，以文件系统时间戳提示后写覆盖风险；看板数据损坏时从资产文件重建。

## 6 数据需求

### 6.1 数据模型概述

采用文件系统存储（CON-07），无数据库。核心实体及其文件载体：

```
projects/
  └─ <项目名>/
       ├─ project.json          # 项目元信息（名称/模板/创建时间/工程规则引用）
       ├─ rules.md              # 项目级工程规则（自动注入 F3）
       ├─ docs/
       │    ├─ 需求/            # F1 流水线产出（含阶段记录与最终文档）
       │    └─ 过程档案/        # 澄清记录、评审意见等
       ├─ analysis/             # F3 结构画像与规整报告
       ├─ pipeline/
       │    ├─ state/           # F6 流水线状态存档（断点索引）
       │    └─ tasks.json       # F4 任务拆分清单（含依赖与执行状态）
       ├─ prompts/
       │    ├─ <模块>/<任务>/   # 各模块提示词（含版本子目录）
       │    └─ feedback.md      # G6 效果反馈记录
       ├─ testcases/            # F5 测试用例
       └─ assets/               # .drawio 图示等
```

实体关系（文字描述，drawio 图见附录 B）：项目 1:N 任务单元；任务单元 1:N 提示词（版本化）；项目 1:N 流水线运行记录；提示词 1:N 执行反馈记录。

### 6.2 数据字典（核心数据项）

| 数据项 | 载体 | 类型 | 说明 |
|--------|------|------|------|
| 项目元信息 | project.json | JSON | 名称、模板来源、创建时间、Provider 配置引用 |
| 工程规则 | rules.md | Markdown | 技术栈约定/编码规范/目录约定，自动注入提示词 |
| 任务单元 | tasks.json | JSON | id、所属模块、描述、依赖列表、上下文预算、执行状态 |
| 提示词 | prompts/** | Markdown | 正文 + front matter（版本号、生成参数、模块、关联任务 id） |
| 测试用例 | testcases/** | Markdown | 用例 id、覆盖需求编号、前置条件、步骤、预期结果 |
| 流水线状态 | pipeline/state/** | Markdown+索引 | 当前角色/步骤、已确认产出指针、待确认草稿 |
| 反馈记录 | feedback.md | Markdown | 提示词 id、执行结果、返工原因（单行） |

### 6.3 数据存储与备份

- 存储：全部为文件系统文本文件（Markdown/JSON/.drawio XML），UTF-8 编码；
- 备份：按 NFR-08 定期自动备份至独立备份目录（可配置外部路径/网盘同步目录）；
- 保留周期：备份默认保留 30 天（可配置）；项目删除第一版为直接移除（依赖备份恢复），后续版本可引入回收站机制。

## 7 验收标准

### 7.1 功能验收标准

| 编号 | 功能 | 验收标准（可测试） |
|------|------|--------------------|
| AC-01 | FR-01 | 给定一段模糊需求表述，流水线依序产出需求摘要→澄清→评审结论，每个中间产出均有确认动作与落盘文件；未确认前无法推进 |
| AC-02 | FR-02 | 选择模板创建项目后，目录骨架与模板定义逐项一致；同名目录冲突被阻断并提示 |
| AC-03 | FR-03 | 在 Chrome 中选择一个测试目录，20 秒内（1 万文件以内，预估）产出结构画像与分级规整建议；全程无源文件内容上传（网络面板可验证） |
| AC-04 | FR-04 | 对任一任务自动选择的模块组合必含需求+开发+测试+验收；任一提示词显式携带其上下文预算参数；任务清单含依赖顺序；提示词未经预览定稿不可导出；构造含假密钥的文档导出时被脱敏扫描拦截提示 |
| AC-05 | FR-05 | 生成的用例集同时含功能与业务两类用例且未勾选性能时不出现性能用例；每条用例标注覆盖的任务/需求编号 |
| AC-06 | FR-06 | 流水线进行到任一步骤关闭浏览器，重新打开后可从断点恢复且已确认产出完整无损 |
| AC-07 | FR-07 | 同一提示词修改两次后存在 3 个版本，任两版可差异对比，可回滚到任意历史版本；任务状态标记在看板正确呈现 |

### 7.2 性能验收标准

| 编号 | 指标 | 验收标准 |
|------|------|----------|
| AC-08 | NFR-01/02 | 10 并发用户常规操作响应 ≤ 2 秒（局域网，预估环境） |
| AC-09 | NFR-08 | 触发备份后备份目录出现完整项目快照，且恢复演练可还原项目 |

### 7.3 验收流程

1. 开发方完成自测并提交验收环境（局域网部署实例）；
2. 按第 7.1/7.2 节标准逐项验证，记录结果；
3. 全部 AC 项通过即验收通过；未通过项回到开发修正后复验；
4. 验收结论由项目委托方确认签署。
