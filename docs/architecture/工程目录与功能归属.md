# 工程目录与功能归属

## 决策：模块化单体，按业务纵切、模块内分层

本项目现阶段继续使用单进程 FastAPI + Vue + SQLite。采用适合中大型演进的目录、依赖边界与测试约束，不提前拆成微服务，也不为了层数给每个函数增加空壳接口。独立部署、团队边界或性能需求出现后再用 ADR 决定服务拆分。

## 目录与责任

```text
apps/
  api/src/devworkbench/
    main.py                       # 组合根：挂载路由、错误处理、生命周期、静态站点
    modules/
      planning/                   # 人机共创、版本、阶段门禁、审查
        router.py                 # HTTP 入参/返回、委托应用服务
        application.py            # 用例编排、事务、运行协调
        domain.py                 # 纯数据模型、树/依赖/覆盖规则
        prompts.py                # 业务知识与完整模型响应契约
      model_settings/router.py    # 设置与授权连接测试入口
      workbench/                  # 项目和旧执行闭环兼容边界
    infrastructure/
      persistence/                # SQLite 连接/事务、schema.sql
      models/                     # API/Codex、DPAPI、模型配置
      search/                     # 受限公网检索适配器
      workspaces/                 # 工作区扫描与隔离
      execution/                  # 旧 CI 命令执行适配器
    shared/                       # 无业务归属的错误、同源检查、路径配置
  web/
    src/
      main.ts                     # 唯一前端入口
      app/                        # 应用壳、导航/项目选择、全局样式
      features/planning/          # 共创界面、类型、专属样式
      features/model-settings/    # 模型设置界面
      shared/api/                 # HTTP 客户端
      shared/ui/                  # 可复用确认弹窗
tests/
  api/{planning,workbench,model_settings,infrastructure}/
  architecture/                   # 自动依赖方向约束与路径稳定性
  support/                        # 合成数据/测试构建器；不可被生产代码导入
  manual/                         # 临时浏览器 fixture；不能冒充真实模型
docs/
  architecture/                   # 工程规则与 ADR
  product/                        # 当前产品设计/范围
  contracts/                      # API、数据协议
  verification/                   # 已完成验收记录/冻结样例
  archive/v1/                     # 旧文档和原型，仅历史参考
legacy/v1/                        # 旧实现；不参与当前启动或源码索引
workspace/                        # 运行数据/私密配置；不提交、不索引
backups/                          # 数据备份；不提交、不索引
```

## 依赖规则

- 后端方向：`main → modules/router → application → domain / infrastructure → shared`。允许 router 直接使用适配器实现很小的配置用例；复杂业务进入 application。
- `shared` 不导入业务或基础设施；`infrastructure` 不导入业务模块；业务模块不导入别的模块内部。真正需要跨模块协作时先写契约/ADR，再在组合根装配明确服务，不通过数据库表随意绕过边界。
- `domain` 不依赖 HTTP、数据库、文件系统和子进程；应用服务不导入路由。API 中不写 SQL，不在共享工具中塞审批业务。
- 前端方向：`app → features → shared`；feature 不导入另一个 feature 或 app；共享组件不导入业务组件。跨 feature 状态由 app 编排，重复工具经过两个真实使用点再提升为 shared。
- Python 使用 `devworkbench.*` 绝对导入。前端当前使用相对导入，不随意增加绕过边界解析的别名。
- `tests/architecture/test_boundaries.py` 检查上述导入边界，并用违规样例自测；它是静态防线，不声称替代人工审查动态导入、SQL耦合或运行时行为。

## 新功能放哪里：固定操作顺序

1. 定义业务能力及与现有模块关系，先更新产品/契约文件。已有能力放进原模块；独立能力才新建 `modules/<capability>` 与 `features/<capability>`。不要按“新需求”新建任意根目录。
2. HTTP DTO 和路由进 router；状态规则/不变量进 domain；用例及事务进 application；供应商 SDK、网络、磁盘和数据库机制进 infrastructure。模块只有一个小接口时不强制生成所有空层。
3. 组件/类型/样式优先与 feature 同目录。单个大组件可逐步拆为该 feature 下的 components/composables，禁止未经使用证据提前生成通用框架。
4. 同步增加所属 `tests/api/<capability>` 测试。共享测试构建器进 support，禁止测试文件彼此导入。后续真实端到端自动化统一在 `tests/e2e` 建立，不与手动 fixture 混淆。
5. 数据结构变化新增有版本号的迁移与回滚说明；当前 schema.sql 只承载原有建表基线，既有轻量兼容 ALTER 保留。本次没有引入未经验证的迁移框架。
6. 跑完整回归、类型检查、构建和架构检查。维护 AOCI 当前机器签发的全部候选；不要只加一个目录说明便认为索引完成。

## 运行与打包边界

- Python 使用 src 布局，`pyproject.toml` 是安装与测试配置唯一入口；打包包含 schema.sql。开发安装 `python -m pip install -e ".[dev]"`。
- 未安装开发包也可从仓库根执行 `python -m uvicorn devworkbench.main:app --app-dir apps/api/src --host 127.0.0.1 --port 8642`。
- 源码 checkout 的默认数据根固定在仓库 workspace，不跟随当前 shell 目录。安装到其他环境应显式设置 `DEVWB_HOME` 与 `DEVWB_WEB_DIST`。
- 单进程限制、审批门禁、API 路径与数据格式不因重构改变；不运行数据库重置，不修改模型凭据，不触发付费模型。

| server/core/planning*.py | modules/planning；公网检索独立放 infrastructure/search |

| server/core/db.py | infrastructure/persistence；稳定路径放 shared/paths.py |
| server/core/provider.py、model_settings.py | infrastructure/models |
| frontend | apps/web |
| tests/test_*.py | tests/api 下所属能力；共用数据放 tests/support |
| docs/v2 | docs/product、contracts、verification |
| docs/需求、设计、原型、过程档案、assets | docs/archive/v1（相互相对链接保留） |
