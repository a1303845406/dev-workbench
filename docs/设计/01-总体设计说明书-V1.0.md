## 1 引言

### 1.1 编写目的

本文档给出"开发工作台"一期的总体架构、技术选型、模块划分与关键横切机制设计，作为详细设计、原型设计、开发任务拆分与测试设计的基准。与本文配套的交付物见《00-设计阶段交付清单》。

预期读者：产品设计人员、开发团队、测试团队。

### 1.2 设计原则

1. **文件系统即数据库**（CON-07）：全部持久化为 UTF-8 文本（Markdown / JSON / .drawio XML），Git 友好，无数据库；
2. **编排可复现**（FR-04 规则 9）：任何一次模型调用都可以从落盘的输入包完整还原、重放；
3. **并行不依赖**（CON-13）：协同工具全部走"格式适配 + 文字指引"，缺失不阻断主流程；
4. **localhost 单机优先**（P-01）：不做鉴权、不做网络暴露设计实现，但结构上保留二期演进接入点；
5. **配置驱动**（NFR-07）：模板、模块提示词、硬约束包、复杂度映射、工具注册表全部为可编辑配置文件，行为调整不改代码。

### 1.3 需求编号引用约定

本文引用 SRS 条款采用 `FR-xx / NFR-xx / CON-xx / AC-xx / G-xx / S-xx / FU-xx / P-01` 编号，与《开发工作台需求规格说明书-V1.2.md》一致，不重复展开需求原文。

## 3 总体架构

### 3.1 架构总览

系统为**单机单进程 Web 应用**，分层结构如下（详见 `docs/assets/系统架构图.drawio`）：

```
┌─────────────────────────────────────────────────────────┐
│ 浏览器层：前端 SPA（Vue 3）                                │
│  项目列表/工作台 · 流水线对话区 · 提示词工作区 ·            │
│  任务看板 · 版本对比 · 工具注册表 · 只读设置页              │
└───────────────▲─────────────────────────────────────────┘
                │ REST + SSE（http://127.0.0.1:<port> 回环）
┌───────────────▼─────────────────────────────────────────┐
│ 服务端：Python 3.12 + FastAPI（单进程，Uvicorn 托管）       │
│  API 路由层 → 领域服务层：                                  │
│   FR-01 流水线引擎 · FR-04 编排器 · FR-03 扫描器            │
│   FR-08 适配导出器 · 脱敏扫描器 · 配置中心                  │
│   落盘服务 · 备份调度器 · Provider 抽象层                   │
└───────────────▲───────────────▲─────────────────────────┘
                │ 原子文件读写    │ HTTPS
┌───────────────▼──────────┐  ┌─▼──────────────────────────┐
│ 本机文件系统              │  │ 外部服务/路径                │
│  projects/（项目工作区）   │  │  LLM Provider API（G-03）   │
│  configs/（产品级配置）    │  │  本机项目路径（白名单，FR-03）│
│  backups/（每日快照）      │  │  协同工具（并行使用，CON-13） │
└──────────────────────────┘  └────────────────────────────┘
```

### 3.2 进程与部署模型

| 项 | 设计 |
|----|------|
| 进程形态 | 单个 Uvicorn 进程：同端口托管 REST API、SSE 通道与前端构建产物（SPA 静态资源）；开发期前后端分离双端口，交付形态单端口 |
| 绑定地址 | **强制绑定 `127.0.0.1`**，启动参数不提供改绑网络的入口（NFR-03 / P-01 的结构性保证）；仅监听端口可配置 |
| 并发模型 | asyncio 事件循环。流水线/编排为进程内后台任务（作业注册表管理），单机单用户为主（NFR-01），预留 10 人并发的连接层能力但一期不做队列化 |
| 会话状态 | 服务端**无会话**：无登录、无 Cookie；前端为瘦客户端，状态权威源在文件系统（FR-06） |
| 长任务生命周期 | 模型调用/扫描等长任务在服务端后台协程执行，前端经 SSE 订阅进度；浏览器关闭不影响服务端任务继续执行与落盘 |
| 静态资源 | 一期随服务端分发（`app 静态目录`），不做 CDN；离线可用（localhost 无外网依赖） |

## 4 技术选型

| 层 | 选型 | 理由与说明 |
|----|------|-----------|
| 服务端语言/框架 | Python 3.12 + FastAPI + Uvicorn | CON-08 指定 Python/FastAPI 方向；Pydantic v2 做请求/响应与 JSON Schema 校验；原生 async 支撑 SSE 与编排协程 |
| HTTP 客户端 | httpx（async） | Provider 调用；流式读取 SSE 增量；超时/重试可配 |
| 服务端推送 | SSE（StreamingResponse） | 单向进度推送足够（5.4 约定 SSE）；比 WebSocket 简单、自动重连、无额外依赖 |
| 前端框架 | Vue 3 + TypeScript + Vite | SPA（CON-08）；中文生态与组件库成熟；构建产物为纯静态文件 |
| UI 组件库 | Element Plus | 桌面后台风格开箱即用，中文文案齐全，覆盖表单/表格/树/对话框/步骤条 |
| 状态管理 | Pinia | 项目/流水线/看板状态集中管理；SSE 事件驱动更新 |
| Markdown 渲染 | markdown-it + DOMPurify | 渲染需求文档/提示词预览；DOMPurify 防注入（提示词含外部工具指引文本） |
| 版本对比 | 自研轻量行级 diff 并排视图（difllib 算法） | 一期仅 Markdown 文本对比（AC-07），不引入 Monaco 等重编辑器；编辑器用带行号 textarea + 实时预览 |
| drawio | 不内嵌编辑器：一期以 .drawio 文本文件下载 + 本地 drawio 桌面版/VS Code 插件打开（IR-03）；只读预览以 XML 校验 + 文件树呈现 | 内嵌 drawio viewer/编辑器收益低、体积大；CON-12 只约束产物格式。是否加只读预览列为开发期可选增强 |
| codegraph | **适配层接口 + 双实现候选**：`AOCI-CODE 外部进程封装`（POC 优先验证）与 `自研 tree-sitter（Python 绑定）` | CON-11 / 批次 0 POC 决定，接口先行使选型不阻塞其他模块开发（见《05-批次0-POC方案》） |
| 定时任务 | asyncio 后台循环（备份调度） | 单机单进程，无需引入 Celery/APScheduler 重依赖；备份周期可配 |
| 测试 | pytest + httpx ASGI 测试；前端 Vitest | 收口于 A7 类任务；本文不展开 |
| 打包分发 | 一期：源码 + 启动脚本（Windows bat / Linux sh，自动建 venv）；可选 PyInstaller 单文件（开发期评估） | localhost 单机工具，分发轻量化 |

> 标注：前端框架（Vue vs React）为设计阶段建议决策（ADR-1），项目计划阶段确认后不再变更。

## 6 关键横切机制

### 6.1 落盘与状态一致性（FR-06 P0）

1. **原子写**：所有写入 = 写同目录临时文件 → `os.replace` 原子替换；JSON 落盘前 schema 校验；
2. **确认即落盘**：用户"确认"动作的事务序 = 写产出文件 → 更新状态索引 → 应答前端；任一步失败则整体失败，前端保留编辑态可重试（SRS FR-06 规则 1）；
3. **状态索引**：`pipeline/state/index.json` 记录各流水线当前位置与产出文件指针，是恢复（P1）与工作台"进行中"标记的单一事实源；
4. **损坏防护**：JSON/Markdown 解析失败时回退最近完好版本（保留 `.bak` 滚动副本 ×3）并提示回退位置（FR-06 异常处理）；
5. **占用提示**（S-04）：写操作带轻量文件锁（`<目标>.lock`，含窗口 id 与时间戳），检测到他锁即告警不阻断。

### 6.2 编排器骨架（FR-04 规则 9，详细算法见《04-核心机制详细设计》）

- 任务 DAG 来自 `pipeline/tasks.json`；编排计划 `plan.json` 为"任务×模块"环序列（拓扑序 + 并行分组）；
- 每环 = 一次**无状态** Provider 调用；输入包四层（角色/全局/任务/上游）组装后先过预算校验，再发起调用；
- 环产出 = 正文 + 交接摘要；连同完整输入包全量落盘 `pipeline/orchestration/<环>/`；
- 环失败重试（默认 3 次可配）后挂起；恢复时从挂起环继续，前序环不重算（AC-14④）。

### 6.3 Provider 抽象层

```text
ProviderConfig（configs/providers.json，脱敏）      环境变量（G-03）
{ "name": "...", "base_url": "...",                 DEVWB_PROVIDER__<NAME>__API_KEY
  "model": "...", "temperature": ... }              （进程启动时注入，永不落盘/入备份/入日志）
```

- 接口：`async chat(messages, *, stream_callback, budget=None) → LLMResult`；`LLMResult = {text, handoff?, usage?}`；
- 流式：服务端将增量转发至前端 SSE 通道（进度指示，NFR-02）；
- 用量采集点预留：`usage` 字段透传记录进环调用记录（二期 G8 直接启用，无结构改动）；
- 失败分类：可重试（超时/5xx/限流）与不可重试（鉴权/参数），驱动编排器重试与提示策略（FR-01/FR-04 异常处理）。

### 6.4 配置中心与热加载

- 产品级配置全部在 `configs/`；服务端以 **mtime 检测**实现"保存即生效"，无需重启（AC-11）；
- 每类配置带 `schemaVersion` 与（硬约束包）`version`；装载失败 → 回退最近完好副本并在设置页标红提示；
- `/api/settings` 聚合输出当前生效值（Key 一律脱敏为 `***`），只读（S-02）。

### 6.5 安全设计（一期 localhost）

| 机制 | 设计 |
|------|------|
| 网络边界 | 绑定 127.0.0.1；启动横幅打印"仅本机访问"；文档警示局域网暴露前必须实施 FU-02/FU-05（NFR-03） |
| 路径白名单 | FR-03 扫描与 FR-04 文件引用仅允许：项目工作区 ∪ 用户显式登记的扫描根目录（`project.json.scan_roots`）；解析真实路径（realpath）后前缀校验，拒绝越界（NFR-04） |
| 遍历防护 | 符号链接默认不跟随；`..` 归一化；深度默认 ≤12、条数默认 ≤20000，超限提示并可调（FR-03 异常处理） |
| 外发知情 | 任何 Provider 调用前，前端必须展示"目标 Provider + 文档清单 + 估算字符量"并获用户确认（G-10 / NFR-12）；API 层记录 `confirmed_at` |
| 脱敏扫描 | 复制/导出链路强制过 sanitize 规则引擎（正则集：密钥/token/密码字段/内网地址段），命中阻断并逐项确认（FR-04 规则 7，宁可阻断不可放行） |
| API Key 管理 | 仅存环境变量或树外加密配置；不入项目目录、不入备份、不入日志（G-03）；日志/落盘输出前过 Key 模式擦除器 |
| 注入防护 | Markdown 渲染统一 DOMPurify 消毒；文件下载校验文件名（防路径穿越） |

### 6.6 备份（NFR-08）

- 默认每日 02:30（可配）对 `workspace/projects/` 做快照：目录复制到 `backups/YYYY-MM-DD/`，保留 30 天滚动清理；
- 快照内容为纯文本资产，**天然不含 Key**（Key 不在数据树）；备份前仍执行一遍 Key 模式扫描，命中即告警；
- 恢复 = 手动复制回工作区；设置页提供"备份目录打开"入口与最近快照清单。

### 6.7 审计日志（NFR-09 / S-05）

- `logs/audit.jsonl`：`{ts, action, project, target, source_ip, hostname, detail}`；
- 关键动作：创建/删除项目、阶段确认、环调用发起（含 Provider 名与预算值）、定稿、复制/导出、配置修改检测、备份执行；
- `source_ip` 一期恒为 `127.0.0.1`，字段保留即为二期鉴权审计基线（S-05）。

## 8 关键技术决策记录（ADR）

| 编号 | 决策 | 理由 | 备选与放弃原因 | 状态 |
|------|------|------|----------------|------|
| ADR-1 | 前端 Vue 3 + Element Plus | 中文生态/后台组件/团队熟悉度 | React + AntD（同等可行，无决定性差异） | 建议采纳，项目计划阶段确认 |
| ADR-2 | 编排/流水线用进程内 asyncio 作业，不引入任务队列 | 单机单用户（NFR-01）；落盘即状态，队列意义有限 | Celery/RQ（重依赖，二期局域网化再评估） | 采纳 |
| ADR-3 | SSE 而非 WebSocket | 单向推送足够；自动重连；实现简单 | WS（双向能力用不上） | 采纳 |
| ADR-4 | codegraph 走适配层接口，POC 定实现 | 选型（AOCI-CODE vs tree-sitter）不阻塞并行开发；AOCI 有 license 待确认风险 | 直接绑定任一实现（风险前置） | 采纳，见 POC 方案 |
| ADR-5 | 一期不内嵌 drawio 编辑器/查看器 | CON-12 只约束产物格式；内嵌 viewer 体积大、离线许可待查 | drawio viewer iframe 嵌入（列为开发期可选增强） | 采纳 |
| ADR-6 | 提示词编辑用轻量编辑器 + 预览，不引 Monaco | 一期编辑以微调为主（G4），行级 diff 并排视图满足 AC-07 | Monaco（体验好但重、打包大） | 采纳 |
| ADR-7 | 原子写 = 临时文件 + os.replace | Windows/Linux 语义一致；崩溃不留半文件 | 直接写（崩溃损坏风险） | 采纳 |
| ADR-8 | 预算校验 = 字符数估算 + token 粗复核（chars/4 经验值 + POC 校准） | 精确 tokenizer 依赖模型族，POC 后冻结口径（G-02） | 逐模型 tokenizer 精确计算（一期成本高，留校准项） | 采纳，POC-2 校准 |
| ADR-9 | 冲突检测 = 关键词级正则告警 | SRS 2.9.3 一期口径 [需技术团队确认]；语义级不做承诺 | 语义检测（一期不承诺） | 设计完成，POC-3 验证误报率 |

## 9 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| AOCI-CODE license 为 NOASSERTION | 深度依赖其产物格式/进程调用存在合规风险 | POC-0 前置确认（POC 方案第 4 节）；tree-sitter 自研为常备退路；适配层隔离（ADR-4） |
| token 估算偏差导致拆分粒度失真 | 任务单元超 IDE 上下文 | 保守系数 0.6（可配）；超预算压缩/阻断双闸（FR-04 规则 9.f）；POC-2 实测校准 |
| 长流水线中途服务进程被杀 | 状态疑义 | 每环先落盘后推进；启动时扫描 state/index.json 做"未完结流水线"标记与恢复入口（P1 能力随批次 5） |
| Windows 路径/编码坑（中文路径、长路径） | 扫描/落盘失败 | 全链路 `pathlib` + UTF-8 显式编码；长路径前缀处理；扫描异常逐项跳过并计入报告 |
| Provider 流式接口差异（中转站兼容性） | 流式失败 | 统一 OpenAI 兼容协议 + 非流式回退开关（Provider 配置项） |
| 硬约束包与项目规则语义冲突漏报 | 提示词约束被放宽 | 关键词级告警 + 人工把关兜底（SRS 2.9.3 口径）；AC-17 用例覆盖 |
