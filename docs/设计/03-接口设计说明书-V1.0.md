## 1 通用约定

| 项 | 约定 |
|----|------|
| 基础路径 | `http://127.0.0.1:<port>/api`（仅回环，NFR-03；无鉴权，AS-01） |
| 数据格式 | 请求/响应 JSON（UTF-8）；文件下载走 `Content-Disposition`；SSE 见 §11 |
| 幂等性 | 写操作以自然键幂等：同名项目创建冲突返回 409；确认/定稿类动作携带 `expected_status` 乐观校验 |
| 占用保护（S-04） | 写接口带 `X-Client-Window` 头（前端窗口 id）；检测到他人 `.lock` 时返回 409 + `PROJECT_LOCKED`，前端弹出占用警告（不阻断只警示） |
| 删除保护（S-01） | 删除项目须携带 `confirm_name` = 项目名，否则 400 + `DELETE_CONFIRM_MISSING` |
| 外发知情（G-10） | 触发模型调用的接口必须携带 `outbound_confirmation: {provider, context_files[], estimated_chars, confirmed_at}`；缺失时 428 + `OUTBOUND_CONFIRM_REQUIRED` |
| 分页 | 列表接口 `?offset=&limit=`，响应含 `total` |

### 1.1 错误模型

```json
{
  "error": {
    "code": "PATH_OUT_OF_WHITELIST",
    "message": "路径不在允许的扫描边界内",
    "detail": { "path": "D:\\other", "allowed_roots": ["D:\\workspace\\..."] },
    "request_id": "req-8f3a",
    "ts": "2026-09-28T10:00:00+08:00"
  }
}
```

| code | HTTP | 场景 |
|------|------|------|
| `PROJECT_NAME_CONFLICT` | 409 | 同名目录已存在（FR-02 规则 3 / AC-02） |
| `DELETE_CONFIRM_MISSING` | 400 | 删除未带项目名二次确认（S-01） |
| `PROJECT_LOCKED` | 409 | 他窗口占用（S-04，警示级） |
| `PATH_NOT_FOUND` / `PATH_OUT_OF_WHITELIST` | 400/403 | FR-03 路径校验（NFR-04 / AC-03） |
| `SCAN_LIMIT_EXCEEDED` | 400 | 深度/条数超上限（FR-03 异常处理） |
| `STAGE_NOT_CONFIRMED` | 409 | 未确认推进（AC-01） |
| `HARD_CONSTRAINT_VIOLATION` | 422 | 模块组合缺需求/开发/测试/验收（FR-04 规则 3） |
| `BUDGET_EXCEEDED_BLOCKED` | 422 | 压缩后仍超预算（FR-04 规则 9.f） |
| `PROMPT_NOT_FINAL` | 409 | 未定稿导出（FR-04 规则 6） |
| `HANDOFF_STALE` | 409 | 交接摘要过期（定稿联动，AC-16，附 `stale_rings[]`） |
| `SANITIZE_BLOCKED` | 422 | 脱敏命中 block 级（FR-04 规则 7，附命中清单） |
| `OUTBOUND_CONFIRM_REQUIRED` | 428 | 模型调用缺外发知情确认（G-10） |
| `PROVIDER_TIMEOUT` / `PROVIDER_RATE_LIMIT` / `PROVIDER_AUTH` | 502/429/401 | Provider 失败分类（驱动重试/挂起） |
| `RING_RETRY_EXHAUSTED` | 200* | 编排挂起事件（*业务成功、任务挂起，见 §7） |
| `SCHEMA_VERSION_UNSUPPORTED` | 422 | 数据/配置版本不兼容（02 文档 §9） |
| `CONFIG_INVALID` | 422 | 配置损坏/校验失败（回退默认 + 提示） |
| `EXPORT_ADAPTER_FAILED` | 502 | 适配导出失败 → 前端提示降级通用 Markdown（FR-08 异常处理） |

## 3 关键端点详设

### 3.1 创建项目（FR-02）

`POST /api/projects`

```json
{ "name": "钛材排产模拟器", "template": "默认模板", "root_override": null }
```

- 校验：名称安全字符集；同名目录冲突 → 409 `PROJECT_NAME_CONFLICT`（AC-02）；
- 副作用：生成 project.json、rules.md 骨架、tools.json（默认清单）、模板目录树；写审计日志；
- 响应：`201 {project 概要, scaffold_report{dirs[], files[]}}`。

### 3.2 FR-01 阶段对话（无状态轮次）

`POST /api/pipelines/{plid}/chat`

```json
{
  "stage": "S1",
  "user_input": "我想做一个……",
  "outbound_confirmation": { "provider": "官方-主模型", "context_files": ["滚动底稿.md"], "estimated_chars": 5200, "confirmed_at": "…" }
}
```

- 服务端组装：①该阶段角色提示词（configs/modules/requirement-*.md）+ ②底稿全文快照 + ③用户输入 → 单次 Provider 调用（FR-01 规则 8）；
- 响应（同步阻塞或 SSE 增量，视 `stream` 参数）：`{round, reply_markdown, draft_update(底稿增量), artifacts[]}`；
- 每轮输入/输出落盘并返回 `round_ref`（AC-15）。

### 3.3 阶段确认

`POST /api/pipelines/{plid}/confirm`

```json
{ "stage": "S3", "comment": "同意，补充一点：…", "expected_status": "draft" }
```

- 事务：产出文件写入 `docs/需求/阶段记录/`（status: confirmed）→ 更新底稿头注 → 更新 state/index → 202 返回下一阶段；
- 未确认推进返回 409 `STAGE_NOT_CONFIRMED`（AC-01"未确认前无法推进"）。

### 3.4 模块组合建议与拆分（FR-04）

`POST /api/projects/{pid}/compose`

```json
{ "complexity": "中等", "context_file_ids": ["docs/需求/需求规格说明书.md"], "user_modules_override": null,
  "outbound_confirmation": { "…": "…" } }
```

- 逻辑：读 complexity-map.json → 校验硬约束（缺需求/开发/测试/验收 → 422 `HARD_CONSTRAINT_VIOLATION`）→ 按任务描述逐条建议模块与拆分草案；
- 响应：`{modules_selected, tasks_proposal[{title, module, description, acceptance, req_refs, est_chars}], deviation_from_map: bool}`。

`POST /api/projects/{pid}/split`：对 proposal 执行预算拆分（超预算单元递归拆分，FR-04 异常处理），落 `pipeline/tasks.json`，返回任务清单与 DAG。

### 3.5 编排计划与执行

- `GET /plan`：返回 plan.json + 每环输入包预览摘要（四层字符量占比，供预算审查）；
- `PUT /plan`：`{rings:[{ring_id, seq, parallel_group}]}` 人工调序（9.e 可预览可调整）；
- `POST /plan/confirm`：状态 → running；编排器启动（拓扑序 + 并行组内并发）；
- 环执行事件走 SSE（§11）；`RING_RETRY_EXHAUSTED` 时 plan 状态 → suspended，`resume_hint` 指明挂起环；
- `POST /plans/{id}/resume`：从挂起环继续，前序环不重算（AC-14④）。

### 3.6 提示词定稿与定稿联动（AC-16）

`POST /api/prompts/{id}/finalize` 响应：

```json
{ "status": "final", "version": 2,
  "handoff_stale": { "affected_rings": ["R010", "R011"], "action_required": "regen-handoff" } }
```

前端据 `handoff_stale` 弹出提示条与"一键重新生成摘要"按钮（调 `/regen-handoff`）；下游环组装输入包时服务端强制取最新定稿对应摘要。

### 3.7 导出（FR-08 / 脱敏门）

`POST /api/projects/{pid}/exports`

```json
{ "format": "spec-kit", "scope": { "requirements": true, "tasks": true, "prompts": false } }
```

- 流程：装配内容 → 脱敏扫描（block 命中 → 422 + 命中清单；confirm 命中 → 200 `{pending_confirm:[…]}`，二次调用带 `sanitize_confirmed: true` 放行）→ 生成 exports/ 产物 → 201；
- 适配器失败 → 502 `EXPORT_ADAPTER_FAILED`，前端提示降级通用 Markdown（FR-08 异常处理）。

## 4 SSE 事件设计（NFR-02 异步进度）

`GET /api/events?project=<pid>`（text/event-stream；心跳 15s；`Last-Event-ID` 重连补发最近 100 条缓存）

| event | data 要点 | 消费方 |
|-------|-----------|--------|
| `scan.progress` | `{job_id, files_done, files_total, phase}` | FR-03 进度条 |
| `scan.completed` | `{job_id, resumable}` | 结果页刷新 |
| `pipeline.state_changed` | `{plid, stage, status}` | 步骤条 |
| `ring.started` / `ring.delta` / `ring.completed` | `{ring_id, task, module}` / 流式文本增量 / `{output_chars, budget_actual, handoff_chars}` | 编排执行视图（流式预览） |
| `ring.failed` / `ring.suspended` | `{ring_id, error_code, retries}` | 挂起提示 |
| `plan.status` | `{plan_id, status, done_rings, total}` | 进度总览 |
| `handoff.stale` | `{prompt_id, affected_rings}` | 定稿联动提示（AC-16） |
| `config.reloaded` | `{config, version}` | 设置页（AC-11 免重启生效的可视反馈） |
| `project.lock_warning` | `{holder_window, ts}` | 占用警示（S-04） |
| `backup.completed` | `{date, files, skipped_key_hits}` | 设置页 |

## 5 Provider 抽象层（内部接口）

```python
class LLMProvider(Protocol):
    async def chat(
        self,
        messages: list[Message],            # 四层输入包已由上层组装为 messages
        *,
        model: str,
        stream_cb: Callable[[str], Awaitable[None]] | None = None,
        max_output_chars: int | None = None,   # 交接摘要上限等输出约束
        timeout_s: float = 120,
    ) -> LLMResult: ...

@dataclass
class LLMResult:
    text: str
    usage: dict | None          # 透传（G8 预留）：prompt_tokens/completion_tokens
    finish_reason: str
    provider: str
    model: str
```

- 工厂按 providers.json 实例化；Key 仅在请求头组装瞬间从环境变量读取（G-03）；
- 失败映射：`httpx.TimeoutException → PROVIDER_TIMEOUT`（可重试）、`429 → PROVIDER_RATE_LIMIT`（可重试，退避）、`401/403 → PROVIDER_AUTH`（不可重试）。

class StructureIndexProvider(Protocol):

## 7 长任务作业模型（内部约定）

- 扫描/编排等长任务统一 `JobManager`：`{job_id, kind, project, status(running|suspended|done|failed), progress, resume_token}`；
- 作业状态同步落盘（scan 摘要 / plan.json），**文件系统为权威态**——服务重启后作业按落盘状态重建为 suspended，可恢复（FR-06）；
- `RING_RETRY_EXHAUSTED` 等业务级"挂起"以 HTTP 200 + 状态字段表达，仅协议级错误用 4xx/5xx。

## 8 外部格式接口（IR-03 / IR-04）

| 接口 | 约定 |
|------|------|
| drawio 文件 | 产物为合法 mxGraphModel XML（CON-12）；服务端写前做 XML 良构校验；不做图形渲染 |
| Spec Kit 适配 | `spec.md`（正文=需求文档定稿）+ `plan.md`（实现形态细化区提取）+ `tasks.md`（任务清单含依赖编号） |
| Taskmaster 适配 | `PRD.md`（纯文本需求）+ `tasks.json`：`[{id, title, description, details, dependencies:[id], status}]` |
| OpenSpec 适配（存量改造） | `changes/<变更名>/{proposal.md, tasks.md}`，proposal 含动机/方案/影响面 |
| 通用 Markdown | 原样导出 |
