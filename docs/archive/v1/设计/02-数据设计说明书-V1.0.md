## 1 存储总原则

1. **全部为 UTF-8 文本文件**（Markdown / JSON / .drawio XML），无数据库（CON-07）；换行符统一 LF（`.gitattributes` 约束）；
2. **schemaVersion 强制**（S-03）：所有 JSON 文件首层含 `"schemaVersion": 1`；读取时校验，未知大版本拒绝处理并提示升级；
3. **原子写**：临时文件 + `os.replace`（总体设计 6.1）；
4. **人类可读优先**：JSON 用 2 空格缩进落盘；Markdown 为主要可读载体，JSON 只承载机器消费的结构（任务/计划/状态/注册表）；
5. **Key 隔离**（G-03）：Provider API Key 不出现在本说明书定义的任何文件中；
6. **路径即标识**：实体 id（项目名、任务 id、提示词 id）同时编码进路径，但路径只使用安全字符集：`[A-Za-z0-9_\-\u4e00-\u9fa5]`，创建时校验（防路径注入/跨平台问题）。

## 4 FR-01 滚动底稿（六区结构）

`docs/需求/滚动底稿.md` 是 FR-01 的状态载体（FR-01 规则 3/8：底稿即状态，任意轮次可复现）。模板固定六区：

```markdown
# 滚动工作底稿 · <项目名>
> schemaVersion: 1 · 流水线id: fr01-<ts> · 当前阶段: S3 · 更新时间: <iso8601>
> 维护: FR-01 流水线引擎（人工可读可改，改后以文件为准）

## 一、项目语境
<!-- 项目名/目录/干系人/部署形态等 5W1H 沉淀 -->

## 二、原始表述记录
<!-- R1/R2/...：逐条原文引用 + 模糊点标注（[模糊: …]） -->

## 三、需求摘要滚动区
<!-- B/F/N/C 四类清单表格；每行含 编号|描述|来源Rxx|状态(开放/澄清中/已确认) -->

## 四、轮次记录
<!-- 第 N 轮：提问 / 回答 / 结论；每轮含模型调用指针（见 .state.json 轮次索引） -->

## 五、范围冻结区
<!-- S5 产出：业务冻结记录 / 功能·非功能清单冻结记录 / 变更流程记入 -->

## 六、实现形态细化
<!-- 阶段性技术讨论沉淀，不进入 SRS 正文 -->
```

**规则**：
1. 每阶段推进后由引擎重写「当前阶段」头注并追加对应分区内容；重写 = 整文件原子替换；
2. 每轮对话调用的输入组装 = 角色层（该阶段角色提示词）+ 状态层（底稿全文快照）+ 用户本轮输入（FR-01 规则 8）；快照内容同时记入该轮阶段记录文件，保证 AC-15 可还原；
3. 底稿损坏（结构区缺失）时：从 `阶段记录/` 最近完好阶段重放重建，提示用户回退位置（FR-06 异常处理）。

### 4.3 阶段记录文件

`阶段记录/S3-澄清追问-<seq>.md`：

```markdown
---
stage: S3
seq: 2
round: 5
status: confirmed            # draft | confirmed | skipped(仅S5)
confirmed_at: 2026-09-28T10:30:00+08:00
model_calls:                 # 本阶段各轮调用指针 → pipeline/state/<id>.state.json
  - round: 5
    input_ref: "state#fr01-1727...#round5"   
---
## 产出
<该阶段产出正文>

## 确认
- 用户意见：…
- 确认时间：…
```

> 确认门（AC-01）：`status: confirmed` 文件存在才允许引擎推进下一阶段；`draft` 不可推进。

## 6 产品级配置 Schema（configs/，NFR-07，热加载）

### 6.1 目录模板 templates/<模板名>/template.json

```json
{
  "schemaVersion": 1,
  "name": "默认模板",
  "description": "通用开发项目目录规范",
  "dirs": ["docs/需求", "docs/过程档案", "docs/assets", "src", "tests"],
```

`rules.md.tmpl` 为工程规则骨架（§7.2）。用户"保存为自定义模板" = 将现有目录结构反向生成 template.json + 内容文件。

### 6.5 脱敏规则 sanitize-rules.json

```json
{ "schemaVersion": 1,
  "rules": [
    { "id": "api-key",   "pattern": "(sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{30,})", "severity": "block" },
    { "id": "password",  "pattern": "(?i)(password|passwd|pwd)\\s*[:=]\\s*\\S+", "severity": "confirm" },
    { "id": "intranet",  "pattern": "(10\\.\\d{1,3}\\.\\d{1,3}\\.\\d{1,3}|192\\.168\\.\\d{1,3}\\.\\d{1,3})", "severity": "confirm" }
  ] }
```

`block` = 命中即阻断导出；`confirm` = 逐项用户确认后方可放行（FR-04 规则 7）。

### 6.6 通用硬约束包 constraints-package.md（2.9.1）

```markdown
---
schemaVersion: 1
package_version: 1.0.0            # 随生成参数归档（AC-17③）
overridable: []                   # 初始集全部不可豁免（2.9.3-4）
conflict_keywords:                # 放宽性表述检测词（一期关键词级，2.9.3-2）
  - "允许硬编码" ; "可以跳过测试" ; "无需注释" ; "可静默吞异常"
---
## 安全
- 禁止硬编码密钥/密码/令牌/连接串；不得在代码、注释、日志中残留敏感信息
## 依赖纪律
- 不得引入项目工程规则未约定的第三方依赖；确需引入时须显式说明理由并标记
## 改动边界
- 仅修改任务描述范围内的代码与文件；不得删除、重写或"顺手重构"范围外内容
## 质量底线
- 新增代码须带必要注释；不得静默吞异常；不留未实现占位逻辑且不声明为完成
## 输出纪律
- 不得编造不存在的 API/函数/配置项；不确定时显式声明"未验证"；严格按提示词要求的输出格式与文件路径产出
```

- `规整建议.md`：表格 `编号|类型(自动归位/需人工决策)|对象|建议|风险`（FR-03 规则 3）；
- `扫描摘要.json`：机器可读统计 + `resumable_token`（续扫游标，扫描中断时支持续扫）。

### 7.10 exports/（FR-08 适配导出）

- `spec-kit/`：`spec.md`（需求文档正文对齐）、`plan.md`、`tasks.md`（任务清单含依赖）；
- `taskmaster/`：`PRD.md`（纯文本需求）、`tasks.json`（id/title/dependencies/details 数组结构）；
- 存量项目改造建议（选配 OpenSpec）：`changes/<变更名>/proposal.md` 结构；
- 导出动作保留原件不变，`meta.json` 记录来源版本号。

## 8 .drawio 产物约定（CON-12）

1. 产物一律为 `.drawio`（mxGraphModel XML 文本），UTF-8；文件名与所属文档同目录就近存放或集中 `assets/`；
2. Markdown 文档中以相对路径引用：`![流程图](../assets/xxx.drawio)`；
3. 一期不内嵌编辑器（ADR-5）：下载后用 drawio 桌面版/VS Code 插件打开；服务端仅做 XML 良构校验。

## 9 版本与兼容策略

| 场景 | 行为 |
|------|------|
| 读取到未知 `schemaVersion` 大版本 | 拒绝处理该文件，设置页与项目详情提示"需升级产品或降级数据"；不静默转换 |
| 小版本新增字段 | 读取方忽略未知字段（向前兼容），写回时保留 |
| 迁移 | `schema_migrations` 记录已执行迁移器（id + 时间）；迁移前自动在备份目录做一次快照 |
| 提示词/文档版本 | 只增不改（版本链在 front matter / 文件名 vN），"回滚" = 以旧版内容生成新版本号（AC-07 可追溯） |

## 10 备份与恢复的数据视角（NFR-08 / AC-09）

- 快照 = `projects/` 目录树整体复制至 `backups/YYYY-MM-DD/`（增量可后置优化，一期全量）；
- 备份前运行 Key 模式扫描（6.5 规则集），命中即告警并跳过该文件、记录日志（G-03 双保险）；
- 恢复演练验收：从任一日期快照复制回 `workspace/projects/` 后，项目可打开、流水线状态索引可读、提示词版本链完整。
