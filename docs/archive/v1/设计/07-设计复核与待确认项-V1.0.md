# 设计复核与待确认项 V1.0

> 状态：设计评审稿，未批准开发。本文对本轮初稿中的工程细节作统一校正；发生冲突时以本文为准。需求范围仍以 SRS V1.2.2 为准，不因设计提案而修改需求。

## 1 已复核的边界

- FR-03 的“自动归位”是建议风险等级，不是自动执行授权。只读扫描，确认后产出整改方案，不移动、删除或重写源文件。
- AOCI-CODE 只作为候选；其许可、性能、联网行为均未重新实测。不能把历史调研结论当作已验证事实。若语义索引需外发，须单独确认，不能由本地扫描默认触发。
- POC-1/2/3 本轮均只制定方案。任何降低 AC-03 标准、取消 AC-17 冲突告警的退路须提交需求变更，不能由技术人员直接采用。
- 文档中“采纳”仅表示设计提案选择，不表示用户已批准技术栈或开发。前端框架与依赖清单仍待设计评审。

## 2 必须统一的工程契约

### 预算单位

上下文窗口以 tokens 表达。记录 `context_limit_tokens`、`budget_tokens`、`estimated_input_tokens`、`actual_input_tokens`、`output_reserve_tokens`、`input_chars` 与 tokenizer/估算器版本。初稿中的 `context_limit_chars`、`effective_chars` 等不作为正式窗口字段。字符与 token 不能直接比较或取最大值；`chars/4` 仅是假设，不是已冻结口径。生成 Provider 与外部 IDE 各自校验窗口，并预留输出与协议开销。

### 原子提交与恢复

单文件 rename 不等于多文件事务。正式设计采用不可变 revision 目录：写产物、输入快照、状态和 manifest → 校验完整性及哈希 → 同文件系统原子替换当前 revision 指针。只有已提交 manifest 可被下游读取；崩溃遗留未提交目录不推进状态。Windows 文件占用、磁盘满、fsync 及替换失败进入故障注入验收。

每个调用 attempt 分目录留存，不覆盖失败尝试。恢复先读取提交指针和完整性校验；未知是否完成的外部调用标记 uncertain，由用户决定重试，不能声称模型调用恰好一次。

### 身份与目录

项目使用稳定 projectId，名称仅显示；流水线使用 runId。编排数据按 `pipeline/orchestration/<runId>/` 隔离，内部保存 plan 与各 ring/attempt。任务包含 `modules[]`，环包含 taskId + moduleId；业务投喂状态与生成环运行状态分别存储。

### 依赖与摘要

同任务模块前后关系与跨任务 DAG 均需无环校验，人工调序不能绕过依赖。交接摘要以产出 revision/hash 绑定；解析失败不得截取正文尾部冒充摘要。上游修订使依赖摘要和受影响下游记录 stale，保留旧记录但不能作为当前有效结果。

“自动推进”适用于已获授权且依赖产出有效的环；提示词仍为预览态时不可导出。【已裁决 2026-09-28】用户确认采用**自动推进**（SRS V1.2.3 ⑥）：环生成落盘后自动推进下一环，定稿不阻断推进，仅约束归档导出（FR-04 规则 6）与下游摘要取材（AC-16：下游环执行时若上游交接摘要过期 HANDOFF_STALE，须先按最新定稿重生成）；本稿原"保守采用定稿门后推进"的方案废弃，原型 V1.5 已同步。

### 路径与本机访问安全

路径校验基于解析后的目录祖先关系，不用字符串前缀（避免 workspace-evil 绕过 workspace）。处理 Windows junction/reparse point、符号链接、大小写、UNC、模板路径穿越与校验后替换风险。扫描白名单须本机可信配置明确登记，不能由任意扫描请求自动扩张。

仅绑定回环仍不足防恶意网页请求：限制 Host/Origin、拒绝任意 CORS、写接口需同源防 CSRF 机制，校验 Content-Type。该机制不是一期用户账号体系。

### 外发、脱敏与日志

外发确认绑定 Provider、模型、文件内容哈希、规则版本及输入快照。批次授权需展示范围；范围变化重新确认。服务端校验授权，不信任客户端随意提交的时间戳。

脱敏放行绑定内容哈希、规则版本与逐项处理结果，不接受裸 `sanitize_confirmed: true` 绕过。block 项须修改后重扫，扫描故障 fail closed。原型只演示确认门，不实现安全服务。

Key 不进项目树。Provider 鉴权凭据在写审计或调用记录前剔除；不应对业务源文档静默删改。备份命中敏感项时标记快照不完整并告警，不得跳过文件后仍宣称完整备份成功。

### API 与并发

项目级规则编辑补充 `GET/PUT /projects/{pid}/rules`；保存冲突告警用 200 + warnings 表达，阻断保存才用 4xx。其他窗口占用警告与 revision 乐观锁冲突分开：前者提示，后者返回 409 且不覆盖。幂等键用于创建/确认/导出等写操作，客户端 expected_status 不能替代 revision 校验。

### 配置与备份

热加载校验新配置，失败保持最近完好配置。硬约束包不可降级为空或被项目关闭。运行中调用固定配置快照，新调用采用新版本。备份须捕获一致提交 revision，并核对 manifest/校验和；恢复在隔离目录先验证再替换。
