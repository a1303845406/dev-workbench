## 3. 公开检索验证

- 模型运行中共 4 次搜索尝试：1 次失败，修复后 3 次成功，每次返回 6 条实际搜索摘要。
- 故障是 Bing 将 `www.bing.com/search` 重定向到 `cn.bing.com/search`，而原适配器不跟随重定向。
- 修复为有限次数手动跟随，仅接受 HTTPS、Bing 白名单主机、标准端口、无用户名密码和 `/search` 路径，保留响应体大小限制。
- 精确查询 `site:sqlite.org partial unique index WHERE IS NULL` 的实际结果相关性不佳。后续公开查询改为 `SQLite`，获得 [SQLite 官网](<https://www.sqlite.org/index.html>)、[官方下载页](<https://www.sqlite.org/download.html>) 等真实结果。
- **这些是搜索摘要而不是全文抓取，只能作为 SQLite 一般背景，不能当作部分唯一索引语法的专门证据。** 不把“有结果”写成“技术结论已获权威证明”。

## 5. 实测发现并修复的工作台问题

| 问题 | 修复与验证 |
|---|---|
| Bing 地区重定向导致检索失败 | 受限 HTTPS 重定向；覆盖可信/恶意地址、循环、响应大小等回归 |
| 提示词末尾只有内层 proposal schema，外层 reply/citations/proposal 不够明确 | 改为完整响应 JSON 契约，提升 Node 定义引用；随后真实需求生成成功 |
| 通用失败提示难诊断 | 区分 JSON 位置、白名单结构字段/树原因、HTTP、超时、网络、截断；不把任意异常正文暴露给前端 |
| 无供应商计量，截断不能识别 | 保留白名单 finish_reason 和整数 usage；length 明确拒绝，不把截断当有效候选 |
| 失败响应无法复盘 | 新失败记录保留密钥脱敏正文，最多 500,000 字符，作为纯文本而非候选版本；旧失败无法补回 |
| 树拆分容易混淆包含与依赖、增加空 NOTE 模块凑数量 | 强化提示并保留后端校验/人工审查，不通过静默修补掩盖模型错误 |
| 从对照模式点击原型页签仍显示对照 | 切换设计页签退出对照，最新线上构建实测原型可见、对照关闭 |

失败正文即使 API key 已替换，仍可能含项目敏感信息。它仅保存于本地项目运行记录，不能据此宣称全面脱敏；是否外发资料仍需用户授权。
