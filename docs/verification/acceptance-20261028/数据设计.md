# 数据设计（候选稿，修订版）

## 1. 实体与特性映射
- books：支撑 F-BOOK-CRUD、F-BOOK-ARCHIVE。
- loans：支撑 F-LOAN-OUT、F-LOAN-RETURN。

## 2. books 表
- id INTEGER PRIMARY KEY AUTOINCREMENT（内部ID不可变）
- code TEXT NOT NULL UNIQUE（trim 后 1–64 字符，编码唯一）
- title TEXT NOT NULL（trim 后 1–200 字符）
- isbn TEXT NULL（trim 后可空，不超 32 字符，不校验校验位）
- archived INTEGER NOT NULL DEFAULT 0 CHECK(archived IN (0,1))
- created_at TEXT NOT NULL（服务端 UTC ISO8601 生成）

## 3. loans 表
- id INTEGER PRIMARY KEY AUTOINCREMENT
- book_id INTEGER NOT NULL REFERENCES books(id)
- member_code TEXT NOT NULL CHECK(member_code IN ('A01','A02','A03','A04','A05','A06','A07','A08','A09','A10'))
- loaned_on TEXT NOT NULL（YYYY-MM-DD）
- returned_on TEXT NULL（NULL 表示未归还）
- 日期与先后校验（不可未来、归还≥借出）由应用层在事务内校验，返回 422。

## 4. 部分唯一索引（待实现设计，未联网查证）

CREATE UNIQUE INDEX ux_loans_active_book ON loans(book_id) WHERE returned_on IS NULL;

## 5. 索引
- books.code 唯一索引（由 UNIQUE 生成）。
- loans(book_id, returned_on) 普通索引，支撑历史查询与未归还判定。
- loans(returned_on) 普通索引，支撑未归还筛选。

## 6. 连接与事务边界
- 每连接执行 PRAGMA foreign_keys=ON。
- 借出、归还、归档三种写操作均 BEGIN IMMEDIATE：先校验后写。
- 借出：事务内校验书目未归档、无未归还记录后插入；唯一索引冲突回滚返回 409。
- 归还：UPDATE loans SET returned_on=? WHERE id=? AND returned_on IS NULL，检查 rowcount；为 0 回滚返回 409（无未归还记录或重复归还）。
- 归档：事务内校验无未归还记录后置 archived=1；不可逆。
- 数据库繁忙：有限 busy 等待，超时回滚返回 503 可重试，不误判 409。

## 7. 停服一致备份与恢复
备份：
1. 停止 FastAPI 应用，确认所有连接已关闭。
2. 执行检查点（如 PRAGMA wal_checkpoint(TRUNCATE)），确认 checkpoint 完成。
3. 复制数据库主文件为快照，对快照执行 PRAGMA integrity_check，确认通过。
4. 记录快照时间与校验结果。
恢复：
1. 停止应用，确认无连接。
2. 先整体保留当前主库及 -wal/-shm 文件（改名归档）以便回滚，禁止直接删除唯一历史副本。
3. 离线置换为已验证的干净快照（含必要伴随文件处理）。
4. 启动应用后执行 integrity_check 与基本查询验证；失败则用保留副本回滚。
不得在线只复制主文件而忽略 WAL。不开发自动备份。
